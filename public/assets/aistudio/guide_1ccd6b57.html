۱ ساخت Worker و KV Namespace

ساخت Worker

  1. وارد dash.cloudflare.com شو → Workers & Pages
  2. روی Create Worker بزن، نام بده (مثل tel-bale-bridge)، Deploy
  3. روی Edit code بزن

ساخت KV و اتصال به Worker

  1. Workers & Pages → KV → Create namespace → نام BRIDGE_KV
  2. به صفحه‌ی Worker برو → Settings → Bindings → Add → KV namespace
  3. Variable name: KV (دقیقاً همین — حساس به حروف بزرگ/کوچک)
  4. KV namespace: BRIDGE_KV رو انتخاب کن → Deploy
🚨
اگر binding با نام KV ست نشه، Worker خطای KV binding missing میده.

۳ تنظیم Secretها (مهم)

در Worker → Settings → Variables یا با Wrangler:

ناممقدارپروژهتوضیح
ADMIN_PASSWORDرمز قویهر دورمز ورود به dashboard
REQUIRE_LICENSE0V-Connectغیرفعال‌سازی سرور لایسنس خارجی
WEBHOOK_VERIFY1Tel-Baleفعال‌سازی secret_token در webhook
bash
wrangler secret put ADMIN_PASSWORD
echo "0" | wrangler secret put REQUIRE_LICENSE  # V-Connect
echo "1" | wrangler secret put WEBHOOK_VERIFY    # Tel-Bale
⚠️
اگر ADMIN_PASSWORD ست نشه: fallback به admin1234 (ناامن).

۶ ثبت Webhook (فقط Tel-Bale)

در dashboard → کارت 🔗 وب‌هوک → دکمه‌ی ⚡ ثبت Webhookها.

برای تست: یک کاربر به ربات تلگرام /start بفرسته. باید در بله پیام «🔔 کاربر جدید استارت زد» بگیری.

⚠️
اگر webhook فعال باشه، دکمه‌ی «اجرا دستی Polling» خطای ۴۰۹ نمی‌ده — به‌جاش پاسخ {skipped:"webhook_active"} برمی‌گرده.

۸ مهاجرت از نسخه قدیمی

اگر نسخه‌ی قدیمی رو داشتی:

قبل از deploy جدید — backup

bash
wrangler kv:key get --binding=KV "config" > backup.json

V-Connect: انتقال offset

در نسخه‌ی جدید، offset از داخل config به کلید جداگانه منتقل شده. اگر این کار رو نکنی، تمام پیام‌های قدیمی دوباره فوروارد می‌شن!

bash
# استخراج offset فعلی از config قدیمی
wrangler kv:key get --binding=KV "config" | jq .offset > old.txt

# انتقال به کلید جدید (بعد از deploy نسخه جدید)
wrangler kv:key put --binding=KV "offset" "$(cat old.txt)"
